# 内置字库

目标是让 3dsDL 不依赖主机的共享字库也能显示中文：程序自带一份只含界面用字的
字库，启动时先看系统字库有没有汉字，没有再回退到自带的那份。

## 为什么需要

3DS 的共享字库按区域裁剪，只覆盖该系统界面用到的字。第三方程序用到别的词就会缺字，
表现是方块。汉化过的机器因为换过字库所以正常，原装机则不一定。

## 现状调查

`coverage.py` 能读出字库里实际映射了哪些码位：

```sh
python3 tools/font/coverage.py path/to/font.bcfnt
```

拿 SharedFontTool 的两份字库和界面用到的 623 个汉字对照：

| 字库 | 覆盖界面用字 | 说明 |
|---|---|---|
| `cbf_zh-Hans-CN.bcfnt` | 623 / 623 | 字符表够用 |
| `cbf_zh-Hant-TW.bcfnt` | 415 / 623 | 少 207 个简体专用字 |

**但字符表够用不代表能画出来。** 把 CN 那份喂给 Azahar，界面上仍有方块
（`设`、`扫`、`码`、`输`、`软`、`关`、`闭` 等）。字符映射里有，字形却没画出来，
说明问题在字形数据或模拟器的加载方式，不在码表。

所以**不能直接拿现成的共享字库当内置字库**，得自己生成一份。

## 计划

1. 从界面文本取出要用的字（`coverage.py` 的 `catalog_chars()` 已经是这个逻辑）
2. 用开源字体（思源黑体，OFL）裁出这些字，生成 bcfnt：
   - 一张 512×512 或 1024×1024 的灰度贴图（格式 LA8/A8）
   - CMAP 用 direct 或 table，CWDH 给每个字宽度
3. 放进 `romfs/font/`，启动时 `C2D_FontLoadFromMemory` 加载
4. 探测系统字库：有汉字就用系统的（零开销、和系统风格一致），没有才用自带的
5. 真机验证老 3DS 的显存占用

## 已知风险

- 显存：老 3DS 给程序的显存有限，贴图不能太大
- 字体度量变化会影响 320px 下屏的换行与居中，需要重新量
- TTF → bcfnt 没有现成工具链，得自己写生成器
